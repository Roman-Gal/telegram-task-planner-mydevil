# Telegram Task Planner — MyDevil

Серверна версія українського Telegram-планнера: FreeBSD, Node.js 24, PostgreSQL і HTTPS-вебхук через WorkLook. Ngrok та Windows-панель для роботи сервера не потрібні.

Локальна версія з ngrok і SQLite збережена окремо: [telegram-task-planner](https://github.com/Roman-Gal/telegram-task-planner), початкова ревізія `9f2690340aeb38bd4366445319f1ea71ca9dcffd`.

## Налаштування

Скопіюйте `.env.example` у приватний `.env` (0600), заповніть Telegram-токен, webhook-секрет і `DATABASE_URL`. Реальні дані не додавайте в Git. `OWNER_USER_ID` та `ALLOWED_CHAT_IDS` зберігають контроль доступу груп.

```sh
npm24 ci
node24 --env-file=.env src/index.js
```

На FreeBSD потрібні `pg_config`, заголовки libpq та C++ toolchain для `pg-native`. Версії npm-залежностей зафіксовані в lockfile.

Нагадування, завдання, користувачі, чернетки й дедуплікація вебхуків зберігаються у PostgreSQL. Синхронний libpq API зберігає транзакційні межі початкового планнера; statement/lock timeout — 5 секунд. Session advisory lock забороняє другий процес із тією самою БД. Запускати тільки один supervisor; цей підхід розрахований на приватного бота, не великий SaaS.

Зовнішній маршрут: `/telegram/webhook`, внутрішній процес слухає тільки `127.0.0.1:18380`. WorkLook перевіряє секрет і передає запит на фіксований локальний порт. Health: `/health`. Схема — `src/schema.sql`.

## Перевірки

`node24 --test` перевіряє логіку на ізольованих SQLite fixtures. З `PLANNER_TEST_DATABASE_URL` ті самі тести працюють на окремій тестовій PostgreSQL; додатково перевіряються 64-бітні ID, параметризований SQL та виключення другого worker. Старий тест міграції legacy SQLite у цьому режимі пропускається; перенесення справжніх даних перевіряється окремим імпортом із порівнянням усіх полів. Тестову змінну ніколи не ставити на production-БД.

У production `loadConfig` вимагає PostgreSQL; SQLite не є робочим сховищем. Дані перед переключенням беруться через SQLite backup API після зупинки локального worker, перевіряються в одній PostgreSQL-транзакції, identity sequence відновлюється. Щоденні pg_dump-бекапи налаштовуються на хості.

Один Telegram-токен має одну активну адресу вебхука. Запуск локальної ngrok-версії з тим самим токеном може переключити її назад. Робочі локальні токени після міграції вимикаються; повернення потребує свідомого переналаштування.
